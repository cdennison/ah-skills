- Investigate reasons for duplicates in `skills_export_top.csv` (50,000 rows, 5,620 distinct `name` values appear more than once). Analyzed by grouping rows on `name` and comparing `(owner, repo)` and `content_hash` within each group. Found four distinct causes, not one:
  1. **Same repo, different target-agent directory** (2,001 name-groups affected). The same skill is checked into multiple platform-specific locations in one repo — e.g. `affaan-m/ECC` has `skills/tdd-workflow/SKILL.md` (Claude convention) plus `.agents/skills/tdd-workflow/SKILL.md` (~91 occurrences) and `.kiro/skills/tdd-workflow/SKILL.md` (~17 occurrences), each presumably a copy/symlink target for a different agent tool that expects its own directory convention.
  2. **Same repo, localized docs copy** (also within the 2,001 same-repo/diff-hash group). e.g. `affaan-m/ECC` has `docs/ja-JP/skills/...`, `docs/zh-CN/skills/...`, `docs/zh-TW/`, `docs/es/`, `docs/tr/`, `docs/ko-KR/` — translated SKILL.md files alongside the English original. These are legitimately different `content_hash` (translated body text) but the same logical skill.
  3. **Repo mirrored/renamed under a second name** (6,241 rows carry a populated `also_in` field). e.g. every `affaan-m/ECC` skill also lists an `also_in` entry pointing at `affaan-m/everything-claude-code` with the identical path — same owner, same content, just published under two repo names (likely `ECC` is a fork or historical rename of `everything-claude-code`, or both are kept in sync deliberately). This inflates counts even though `export_csv.py` seems to already be folding these into one row's `also_in`/`duplicate_count` rather than emitting two rows — worth confirming this dedup is complete and doesn't miss cases.
  4. **True name collisions across unrelated repos** (3,619 name-groups — the largest category). Different owners independently publish a skill with a common generic name (`tdd`, `brainstorming`, `accessibility`, `implement`) but different `content_hash` and different descriptions/approaches. These aren't duplicates of the same skill at all — they're coincidental naming overlap, most often on short, self-descriptive names that many people would independently choose (verified: 0 cases of identical content across different repos in this dataset — every cross-repo same-name match had a different hash).
